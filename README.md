# 换月提醒

期货换月机会的定时监控。由 GitHub Actions 每 5 分钟跑一次，跑在 GitHub 自己的机器上，不依赖任何人的电脑、也不依赖我的沙箱。

## 它做什么

拿你当前的持仓合约，对后面每一个可交易的远月算「折合每月」：

```
折合每月 = (持仓合约买一 − 远月合约卖一) ÷ 相差月数
```

用的是**对手价**：卖出近月看买一、买入远月看卖一，已含一次买卖价差。超过你设的阈值就推一条到手机（Bark）。

## 配置从哪来

优先级：

1. **网页版 / 安卓 App 上的最新设置**（你改阈值、换持仓都在那儿改）
2. 仓库里的 `config.json`（自动备份，上面拿不到时用它）

也就是说：平时在 App 里改就行，这里不用碰。每次从服务端取到新配置都会自动写回 `config.json`，等于自动备份——哪天服务没了，靠这份备份也能继续跑。

## 两个仓库文件

| 文件 | 作用 | 谁写 |
|---|---|---|
| `config.json` | 阈值、持仓、冷却、开关 | 自动（从服务端同步） |
| `state.json` | 上次推送时间，用来算冷却 | 自动（每次推送后更新） |

想看当前在盯什么，直接看 `config.json` 就行。

## 需要配的 Secrets

| 名称 | 是什么 |
|---|---|
| `BARK_URL` | Bark 推送地址，形如 `https://api.day.app/你的KEY` |
| `SANDBOX_URL` | 配置服务地址，形如 `https://xxx.app.workbuddy.host` |
| `SANDBOX_KEY` | 配置服务的 sharecode |

没配 `BARK_URL` 就不会推送（日志里会说「没配 Bark，跳过」）。
没配 `SANDBOX_URL` 就一直用仓库里的 `config.json`，也能跑，只是改配置得改文件。

## 三个必须知道的限制

**1. GitHub 的定时任务不保证准点**

官方明确说了：高负载时排队的任务会被延迟，极端情况会被丢弃。实际跑下来，延迟几分钟到十几分钟是常态。所以这里的「每 5 分钟」真实含义是「每 5～20 分钟随机一次」。

对换月这种事够用——贴水结构是以天为单位变的，不是以秒。但如果你想抓日内插针式的机会，这个精度不够。

**2. 只在交易时段干活**

北京时间 9:15–11:35、12:55–15:05，铁矿石再加夜盘 21:00–23:05。其余时间直接退出，不浪费额度。

**3. 60 天没有提交会被自动停用**

GitHub 对公开仓库的定时任务有个规矩：长期没有提交活动就停掉。`watch.js` 里有个 `lastKeep` 机制，每 30 天会主动碰一次仓库，正常不会触发。但如果发现推送突然不来了，先来这里看一眼 Actions 是不是被禁用了。

## 本地跑一遍

```bash
BARK_URL="https://api.day.app/你的KEY" node watch.js
```

输出最后一行 `RESULT {...}` 就是这一轮的完整结果：查了哪些品种、有几个可换、推没推。

## 和网页版的关系

网页版负责看盘和改配置，这里负责盯盘和推送。两边的心跳是互通的：

- 这里每跑完一轮，会往网页版回写一次心跳，网页版面板上显示「GitHub 监控中」就是它在干活
- 网页版那边看到这个心跳还在，就会主动让位，不重复推送
- 如果这里超过 8 分钟没心跳（仓库停了、额度用完），网页版会自动接管，退回 1 分钟粒度自己跑

两边互为备胎，不会同时推同一条。
